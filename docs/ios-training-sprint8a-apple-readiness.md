## 3. Account deletion — Apple 5.1.1(v)

**Assessment.** Guideline 5.1.1(v) requires in-app account deletion for apps that **support
account creation**. The VITRUV app does not: accounts are created by an admin/coach (operator
tooling / web admin); the app offers login only, no sign-up, no self-service password reset
(`login_screen.dart`). Strictly, 5.1.1(v) does not apply. Apple reviewers nonetheless often ask;
GDPR Art. 17 (right to erasure) applies regardless of the App Store.

**Decision for Sprint 8A:** no deletion button in the app (a button without a working, legally
defined backend would be a dead button). Documented design + open legal decisions instead.

**What exists today.** Admin can disable or archive a client (`/v1/admin/clients/:id/account`,
`/archive`); disabling revokes sessions (`USER_DISABLED`), writes `ACCOUNT_DISABLED`; users are
never hard-deleted (project rule).

**Design if the owner wants in-app deletion (Sprint 8B candidate):**
1. App: Konto → "Konto löschen" → explanation → password re-confirmation.
2. API `POST /v1/client/me/deletion-request` (rate-limited): status → `DISABLED`, all sessions
   revoked, deletion request event visible to admin/coach. Needs a new `auth_events.type` value →
   **migration 0026** (not created this sprint).
3. After the legally defined retention period: anonymise personal fields (name, e-mail,
   username, profile), keep or delete training history per policy; media/documents deleted.
4. Confirmation to the user (e-mail only if SMTP is configured).

**Legal / owner decisions (not invented here):** retention period for training data and
invoices/contracts (HGB/AO for business records), whether coaching history is anonymised or
deleted, who confirms, response time, wording in the privacy policy.

## 4. Production API configuration — fail closed

`apps/mobile/lib/core/config/app_config.dart` (tests in `config_and_roles_test.dart`):

- Release build (`kReleaseMode`) **refuses to start** unless `--dart-define=APP_ENV=staging|production`
  and `--dart-define=API_BASE_URL=…` are both given.
- URL must be `https`, no user info, no query/fragment, not localhost/loopback/private network/
  emulator alias, not a reserved/internal domain (`.local`, `.test`, `.invalid`, `.example`,
  `.internal`, `.lan`, `.home.arpa`, example.com …), no placeholder words, a dotted host name, no
  IP literals. The error names the setting, never the value.
- The real production API URL is **not** in the repo and was not guessed: owner input.

Build command for the Mac (values from the owner):
```
flutter build ipa --release --dart-define=APP_ENV=production --dart-define=API_BASE_URL=<owner-provided https URL>
```
