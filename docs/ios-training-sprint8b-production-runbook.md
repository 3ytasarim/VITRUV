## 2. API deploy

## 3. Web deploy

  The strict origin check (`Forbidden: invalid request origin`, log `csrf_origin_rejected`) stays

- Smoke: public pages, admin login, a form POST from the canonical host succeeds, the same POST

## 4. nginx / CDN

Template: `docs/deploy/nginx-vitruv.conf.example`.
- Access logs use `$uri` (no query string) → signed `?u=&e=&s=` never logged.
- `/v1/media/training/`: `proxy_buffering off`, no cache, `Range`/`If-Range` forwarded; the API's
  `Cache-Control: private, no-store` untouched.
- Canonical host: http → https, `www.` → apex (or the reverse — must equal `PUBLIC_SITE_URL`).
- CDN (if any): bypass `/v1/*`, keep the query string, no video optimisation.

## 5. Minimum app version (only when needed)

1. Never set a minimum before the corresponding build is **live in the App Store**.
2. Set `MOBILE_UPDATE_URL_IOS` (the real App Store URL) first, then `MOBILE_MIN_VERSION_IOS`.
3. Keep `MOBILE_LEGACY_APP_POLICY=allow` until header-less (pre-8B) builds are gone.
4. Effect: below-minimum app sessions get 426 on `/v1/client/*` → update screen; tokens remain;
   web unaffected. Rollback: unset the variable + restart.
Verified only on the isolated cluster (`sprint8b-app-version.pg.test.ts`).

## 6. Private training media

`TRAINING_MEDIA_VISIBILITY=PRIVATE` with `MEDIA_URL_SIGNING_KEY` set. Rollback: back to `PUBLIC`.

Stage 2 (existing videos) uses `training-media-privatize.ts` steps 1–10 — **no CLI exists on
purpose**. Before production use a separate, reviewed operator script must take an **explicit**
DB URL + storage config (never the root `.env` implicitly), default to dry run, and be approved.
Order: storage snapshot/versioning → inventory (dry run) → copy + SHA-256 verify → flip →
smoke (signed playback, seek, renewal on a real iPhone) → wait period → `removePublicOriginals`
(separate approval; afterwards rollback is impossible). Never run `storage:migrate` with the
production `.env`.
